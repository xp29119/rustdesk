RustDesk 独立登录与统一管理平台方案
日期：2026-10-21
状态：开发中。后台已完成本地测试并部署回环版本；三端登录已接入源码，完整编译和实机测试未完成，不能作为成品分发。

一、已确认的需求
- 使用官方免费 RustDesk Server OSS，不要求用户先连接 AWG。
- Windows、macOS、Android 客户端内置服务器，隐藏服务器设置，关闭官方更新。
- 管理员创建账号，关闭公开注册。每台新设备首次登录后必须由管理员批准。
- 保存可撤销的登录凭证，平时不用反复输入密码。
- 管理网页是可扩展的统一平台；RustDesk 仅是第一个功能模块。
- 目标是即使安装包、服务器 IP、公钥泄漏，未授权的人仍不能使用服务器。

二、无需购买域名的 HTTPS
拟使用 https://8.138.230.183 作为网页和登录 API 地址。
使用 Let's Encrypt 公网 IP 证书（不是让浏览器忽略证书错误）。官方已提供此能力；IP 证书有效期为 160 小时，必须自动续期。
部署前验证服务器访问 ACME 服务的网络，以及 TCP 80/443 的云安全组和本机防火墙。现有 AWG 使用 UDP 443，不与 TCP 443 冲突。
若 ACME 不可达，应先修复连通性，不发送明文登录信息、不关闭证书校验。
更换公网 IP 需要重新申请证书，并更新客户端的固定地址。
官方依据：https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability

三、统一管理平台
采用一个轻量后端、一个网页前端、SQLite 数据库和 systemd 部署，适配当前约 1 GB 内存的服务器；实际资源用量必须压测验证。
公共模块：账号、角色、设备审批、会话撤销、操作审计、平台设置。
RustDesk 当前模块：由服务端观测的 WebSocket 通道开关、时间和流量。尚不能显示实际远控目标或宣称成功登录远端桌面。
已实现接口见 control-platform/README.md；以后其他模块复用账号和权限。
所有管理页面要求管理员登录；“通用平台”不表示公开管理数据。

四、账号和设备的使用流程
1. 管理员创建账号，用户在定制客户端登录。
2. 每个客户端生成自己的设备密钥；新设备进入待审批状态。
3. 管理员看到账号、设备名称、系统、首次登录时间后批准或拒绝。
4. 批准后获得短期访问凭证；长期刷新凭证通过操作系统安全存储保管。服务器只保存刷新凭证摘要，刷新时轮换，检测重复使用。
5. 客户端自动刷新；密码不作为缓存保存。默认 30 天不使用后需要重新登录。
6. 禁用账号或撤销设备后拒绝新连接；活动连接的撤销时限必须在端到端测试中测量并明确展示。
设备标识不能只靠可伪造的机器名称、序列号或 MAC 地址，应结合设备私钥持有证明。
平台登录权限与 RustDesk 被控端密码/本地确认是不同层次；保留原有被控端授权，不给所有设备设置相同远控密码。

五、真正的防盗用边界
免费 OSS 原版没有本方案要求的账号、设备审批和统一权限体系。只改登录页面不满足需求。
需要让服务端注册、协调连接、中继入口都验证账号和已批准设备，而不只校验服务器公钥。
当前实现采用短期访问令牌和设备私钥证明，绑定账号、设备、请求 URL、HTTP 方法、有效期、令牌摘要和一次性标识。审批授权的是设备使用本平台的能力；远控目标仍由 RustDesk 的密码或本地同意机制保护。
所有会修改设备状态、发起连接或分配中继资源的协议路径都必须纳入鉴权。不能保留可绕过认证的原生端口或备用路径。
第一版采用仅开放鉴权后 WSS 入口、后端限制本机访问的方案，并强制中继。已说明它会增加服务器带宽与延迟，后续必须进行资源压测。
没有有效账号和已批准设备凭证的官方客户端，即使知道 IP、公钥和设备 ID，也应无法注册或使用连接/中继服务。API 和测试 WebSocket 后端的拒绝测试已通过，实际 RustDesk 端到端验收尚未完成。
任何方案都不能保证已授权终端被完全攻破后仍绝对安全；需要设备撤销和会话失效能力。

六、日志的真实性
登录和审批记录由账号服务生成，连接授权记录由服务端生成。
P2P 远控的数据可能不经过服务器，准确的会话结束和时长需要客户端上报；界面须区分“服务端观测”“客户端上报”“失联/未知”。不能将一次信令请求称为成功远控会话。
不记录明文密码、访问/刷新令牌、私钥、剪贴板或屏幕内容。

七、发布前必须通过的验收
- 合法账号、新设备：未经审批不能使用；审批后可以正常连接。
- 仅复制安装包、IP、公钥：没有账号和批准设备，注册与中继均被拒绝。
- 使用官方客户端或删除定制客户端的登录界面，仍不能绕过服务端检查。
- 过期凭证、伪造票据、重复使用票据、已撤销设备、新设备冒充已批准设备均被拒绝。
- 账号停用、设备撤销能够阻止新连接；活动连接按定义的时限失效。
- 三端正常重启后恢复登录，注销会撤销凭证；系统安全存储失败时不降级明文保存。
- HTTPS 证书自动续期、恢复备份、服务重启和网络故障场景可用。
- 登录、连接结果、断线记录与实际行为一致。

九、既有路径变化范围
- Cargo 和锁文件：加入受 feature 控制的认证模块及所需密码学、系统存储依赖。
- 初始化、Windows 固定服务器与关于页面：强制内部配置并隐藏入口，feature 关闭时走原逻辑。
- `common::get_api_server` 在定制模式返回空地址，停用原 Pro HTTP 接口推导；独立登录模块使用自己的固定 HTTPS origin，避免将 WSS 信令 URL 错当成旧 HTTP API。
- 更新模块及桌面/手机更新入口：仅定制模式禁用检查、后台更新和手动更新。
- IPC 与 Windows 系统服务：复用现有受保护服务通道的对端授权，加入专用登录请求；发送端在交出密码前核实系统服务身份和可执行文件。
- Flutter 初始化、主页和 Android Application：调用新增登录界面/存储适配；现有被控端密码与系统屏幕权限流程不被替代。
- FRB 1.x 的普通 Rust 桥接不能直接返回 Future。登录桥接使用普通函数投递到显式启动的持久异步工作线程；Android 的凭据及 HTTP 连接由该线程持有，关闭某个窗口或单次请求不会销毁它。没有在现有异步调用中嵌套运行时，也没有修改既有在线查询线程。
- hbb_common 仅增加可选 WSS 请求头提供器及严格 TLS 连接路径；未安装回调的既有行为保留。子模块固定到单一功能提交，未引入其他上游变动。

实施顺序：账号与设备授权服务 → RustDesk 服务端强制鉴权 → 三端登录和安全存储 → 网页模块与日志 → 绕过测试和实机连接验证 → 云编译和签名交付。
